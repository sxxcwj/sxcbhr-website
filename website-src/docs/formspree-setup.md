## 配置与验证

公开地址保存在 `src/config/contact.ts` 的 `formspreeEndpoint`。以后替换表单时先核对后台收件人，再更新这个地址并运行：

```bash
pnpm test
pnpm build
pnpm preview
```

收件人由 Formspree 后台管理，前端不会接受访客指定收件人。不要把任何邮箱密码或管理密钥放入源代码或 VITE 环境变量，浏览器资源会公开。

更换表单后核对标明“网站功能测试”的真实咨询在 Formspree Submissions 与收件邮箱（包括垃圾邮件夹）中的内容，确认字段、中文与多行内容正确。当前已有一条真实记录及用户收件确认；不应为了重复验证而自动重发。发送真实测试邮件应先取得用户授权。

保持服务的反垃圾和人机验证保护。如果实际配置返回 CAPTCHA 错误，当前页面会明确失败并提供邮件草稿；应按该表单实际要求接入验证组件后再上线，不能将验证失败当作成功，也不要自动关闭安全保护。

## 提交行为

- 未配置时仅生成本地邮件草稿，不调用外部服务。
- 在线模式提交中禁止重复点击与修改字段。
- 仅在 HTTP 成功且返回明确的 JSON 接收确认时显示“咨询已提交”；不声称收件箱已经收到邮件。
- 校验失败、网络失败、超时、服务错误、额度限制均保留填写内容。超时或结果不明不自动重试，以免重复发送。
- 邮箱、电话、微信均可作为联系方式；仅合法邮箱值用于 Reply-To。
- 提交字段固定，不上传额外私人数据；隐藏 `_gotcha` 防垃圾字段符合官方规则。
- 可改用邮件草稿，手动发送至现有咨询邮箱。

## 发布

确认提交与通知配置后，将 `dist/static/` 内容复制至仓库根目录，保留 `CNAME`、`.nojekyll` 和历史文件，再提交并正常 push 到 `main`。部署后核对页面，邮箱收件结果单独记录；不得只提交源码就声称自动邮件已经上线。

需要暂停在线提交时，可将地址设为空字符串并重新构建发布，页面会恢复邮件草稿入口。公开 Form Endpoint 不是密钥；邮箱密码、管理密钥及客户资料不得进入仓库。
